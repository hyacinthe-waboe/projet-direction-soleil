1 - Approche Logique 


1.1. Schéma Relationnel
A partir du modèle conceptuel de données proposé par le client, nous avons élaboré le modèle logique de données ci-dessous:


CLIENTS(CodeC, NomC, PrénomC, TelC, MelC)
AEROPORTS_DEP(CodeA, NomA)
CIRCUITS(CodeCI, NomCI, PrixBase,NbPersMax, #CodeCI_Est_Complete)
PAYS(CodeP, NomP, AvisGen)
SITES(CodeS, NomS, TypeS, DescripS)
ANIMATIONS(CodeAN, NomAN, TypeAN, HeureDeb, JourSemaine, #CodeH)
HOTELS(CodeH, NomH, Categorie, VilleH, TelH, MelH)
GUIDES(CodeG, NomG, PrenomG, DatePremier)
ZONE_GEO(CodeZ, ZoneGeo)
ACTIVITE(CodeAC, NomAC, TarifAC)
LANGUE(CodeL, NomL)
MOIS(CodeMois, LibelleMois)
CHOIX ( #CodeC, #CodeA, #CodeCI, DateDepartC, OrdrePreference )
RESERVER (  #CodeC, #CodeA, #CodeCI, DateDepartR, DateResa, NbPers )
MAJORATION ( #CodeA, #CodeCI,  DateDepartM, MontantMaj)
PRATIQUER ( #CodeG, #CodeL, NiveauL )
VALIDITE ( #CodeAC, DateDebut, DateFin ) 
REALISER ( #CodeCI, #CodeAC, DateDepartRe, JourSem )
LOGER ( #CodeCI, #CodeH, JourSe ) 
VISITER ( #CodeCI, #CodeS, JourSe2, HeureVisite, DureeVisite )
AVIS ( #CodeP, #CodeMois, TempMin, TempMax, AvisMens, TempMinMoy, TempMaxMoy )
SITUER ( #CodeCI, #CodeZ, #CodeP ) 
ACCOMPAGNER ( #CodeG, #CodeCI, DateDepartA)


1.2. Commentaires
Lors de l’élaboration du modèle relationnel, on s’est aperçu de quelques modifications indispensables pour garantir le bon fonctionnement de la base de données:


* Un changement des noms des attributs “Date” données sur le dictionnaire de données était nécessaire. “Date” étant une fonction sur notre future base de données Oracle. Donc pour la relation Reserver par exemple, au lieu de mettre “Date” comme nom, nous avons plutôt défini “DateDepartR”. Les noms d’attributs choisis sont : DateDepartC, DateDepartM, DateDepartA, DateDepartRe.
* Tous les noms des relations ont été défini en majuscules.
* Tous les attributs ou tables ayant des accents ont été écrits sans accents.

2.1.8. Requête 8


Énoncé : Donner les coordonnées du client ayant effectué le plus de circuits pour chaque pays.


Requête SQL :
SELECT p.nomP, COUNT(DISTINCT r.codeci) AS nbCircuits, c.nomc, c.prenomc, c.telc, c.melc
FROM clients c, reserver r, circuits ci, situer s, pays p
WHERE c.codec = r.codec
AND r.codeci = ci.codeci
AND ci.codeci = s.codeci
AND s.codep = p.codep
AND r.dateDepartR <= SYSDATE
GROUP BY c.codec, c.nomc, c.prenomc, c.telc, c.melc, p.codep, p.nomP
HAVING COUNT(DISTINCT r.codeci)  =
    (
        SELECT MAX(COUNT(DISTINCT r2.codeci))
        FROM reserver r2, circuits ci2, situer s2, pays p2
        WHERE r2.codeci = ci2.codeci
        AND ci2.codeci = s2.codeci
        AND s2.codep = p2.codep
        AND p.codep = p2.codep
        AND r2.dateDepartR <= SYSDATE
        GROUP BY r2.codeC
     )
ORDER BY p.nomP ASC;


Résultat : 
  

Figure 8: Résultat de la requête 8 sur SQL Developer


Justification :


La requête permet d'identifier les clients ayant effectué le plus de circuits différents dans chaque pays. Elle utilise les tables CLIENTS, RESERVER, CIRCUITS, SITUER et PAYS pour associer les clients aux pays visités. La condition r.DateDepartR <= SYSDATE permet de ne prendre en compte que les circuits déjà effectués. Ensuite, COUNT(DISTINCT r.CodeCI) compte les circuits différents de chaque client, et la sous-requête permet de sélectionner le nombre maximal de circuits pour chaque pays.


Pour vérifier les résultats, on compare les réservations dans RESERVER avec les pays associés aux circuits dans SITUER. Ces valeurs correspondent bien aux résultats retournés par la requête.

2.1.9. Requête 9


Énoncé : Donner les noms des circuits disponibles au départ de Toulouse qui permettent de visiter tous les sites de Tunisie.


Requête SQL :
SELECT DISTINCT c.NomCI
FROM circuits c, majoration m, aeroports_dep a, situer s, pays p
WHERE c.CodeCI = m.CodeCI
AND m.CodeA = a.CodeA
AND c.CodeCI = s.CodeCI
AND s.CodeP = p.CodeP
AND LOWER(a.NomA) = 'toulouse'
AND LOWER(p.NomP) = 'tunisie'
AND m.datedepartm NOT IN (
   SELECT r.dateDepartR
   FROM reserver r
   WHERE r.CodeCI = c.CodeCI
   AND r.CodeA = m.CodeA
   GROUP BY r.dateDepartR
   HAVING SUM(r.NbPers) >= c.NbPersMax
)
AND NOT EXISTS (
   SELECT 1
   FROM situer s2, visiter v
   WHERE s2.CodeCI = v.CodeCI
   AND s2.CodeP = p.CodeP
   AND NOT EXISTS (
       SELECT 1
       FROM visiter v2
       WHERE v2.CodeCI = c.CodeCI
       AND v2.CodeS = v.CodeS
   )
);


Résultat : 


  

Figure 9: Résultat de la requête 9 sur SQL Developer
________________


Justification :


La requête 9 est une division relationnelle : on cherche les circuits, partant de Toulouse, qui visitent tous les sites tunisiens. SQL n’a pas de quantificateur  “pour tout”, donc on le remplace par une double négation équivalente. Donc “le circuit visite tous les sites tunisiens” revient à dire “il n’existe aucun site tunisien que le circuit ne visite pas”. 


Le NOT EXISTS extérieur parcourt les sites tunisiens (ceux visités par un circuit situé en Tunisie). Le NOT EXISTS intérieur vérifie, pour chacun, si le circuit le visite. Un seul site manqué élimine le circuit. Une condition EXISTS supplémentaire garde les circuits disponibles au départ de Toulouse.


Le résultat est “Perles de Tunisie”. Les sites tunisiens sont les sites 1 à 7. Seul ce circuit les visite tous, alors que les quatre autres circuits tunisiens en manquent au moins un. Ce résultat correspond bien à la définition de l’énoncé.

2.2. Requêtes SQL Supplémentaires
2.2.1. Chiffre d'affaires total par départ


Énoncé : Pour chaque départ ayant au moins une réservation, donner le nom du circuit, l'aéroport, la date, le nombre total de voyageurs inscrits et le chiffre d'affaires total généré. Le chiffre d'affaires est calculé à partir du nombre de personnes réservées, multiplié par la somme du prix de base et de la majoration. Classer les résultats par chiffre d'affaires décroissant.


Utilité métier : Comparer les départs selon leur chiffre d'affaires afin d'identifier ceux qui génèrent le plus de revenus pour l'agence.


Requête SQL :
SELECT CI.NomCI, A.NomA, R.DateDepartR, SUM(R.NbPers) AS TotalVoyageurs,
       SUM(R.NbPers * (CI.PrixBase + M.MontantMaj)) AS ChiffreAffaires
FROM CIRCUITS CI, AEROPORTS_DEP A, MAJORATION M, RESERVER R
WHERE CI.CodeCI = R.CodeCI
AND A.CodeA = R.CodeA
AND M.CodeCI = R.CodeCI
AND M.CodeA = R.CodeA
AND M.DateDepartM = R.DateDepartR
GROUP BY CI.CodeCI, CI.NomCI, A.CodeA, A.NomA, R.DateDepartR
ORDER BY ChiffreAffaires DESC;


Résultat : 
  

…
  

Figure 11: Résultat de la requête supplémentaire 1 sur SQL Developer
Justification :


La requête permet de calculer le nombre total de voyageurs et le chiffre d'affaires généré pour chaque départ. Elle relie les tables CIRCUITS, AEROPORTS_DEP, MAJORATION et RESERVER afin d'associer chaque réservation à son circuit, son aéroport et sa date de départ. La clause GROUP BY regroupe les données par départ unique (circuit, aéroport et date). 


Pour chaque groupe, SUM(R.NbPers) calcule le nombre des voyageurs, tandis que SUM(R.NbPers * (CI.PrixBase + M.MontantMaj)) calcule le chiffre d'affaires total du depart. Enfin, ORDER BY ChiffreAffaires DESC classe les résultats pour faire ressortir les départs les plus rentables en premier. 


Pour vérifier les résultats, on constate dans RESERVER que le circuit "Désert de Merzouga", au départ de Marseille le 15/07/2026, possède 3 réservations de 6 personnes, soit 18 voyageurs. Dans CIRCUITS, son prix de base est de 890 €, auquel s'ajoute une majoration de 25 € dans MAJORATION. On obtient donc 18 × (890 + 25) = 16 470 €, ce qui correspond au chiffre d'affaires calculé pour ce départ.






2.2.2. Arbitrage de prix entre présélections d'un même circuit


Énoncé : Pour chaque client ayant présélectionné le même circuit avec plusieurs dates ou aéroports de départ, afficher son nom, son prénom, le circuit, l'aéroport, la date, l'ordre de préférence et le prix total de chaque présélection (prix de base + majoration). Trier les résultats par client et par prix décroissant.


Utilité métier : Observer comment un client classe des départs d'un même circuit dont les prix diffèrent, afin de mieux comprendre l'influence des tarifs sur ses préférences.


Requête SQL :


SELECT C.CodeC, C.NomC, C.PrenomC, CI.NomCI,
       A.NomA, CH.DateDepartC, CH.OrdrePreference,
       CI.PrixBase + M.MontantMaj AS PrixTotal
FROM CLIENTS C, CIRCUITS CI, CHOIX CH,
     AEROPORTS_DEP A, MAJORATION M
WHERE C.CodeC = CH.CodeC
AND CI.CodeCI = CH.CodeCI
AND A.CodeA = CH.CodeA
AND M.CodeCI = CH.CodeCI
AND M.CodeA = CH.CodeA
AND M.DateDepartM = CH.DateDepartC
AND EXISTS (
    SELECT *
    FROM CHOIX CH2
    WHERE CH2.CodeC = CH.CodeC
    AND CH2.CodeCI = CH.CodeCI
    AND (CH2.DateDepartC <> CH.DateDepartC
    OR CH2.CodeA <> CH.CodeA)
)
ORDER BY C.CodeC, CI.NomCI, PrixTotal DESC;




Résultat : 
  

Figure 12: Résultat de la requête supplémentaire 2 sur SQL Developer
Justification : 


La requête permet d'identifier les clients ayant présélectionné un même circuit avec des dates ou des aéroports de départ différents. Elle utilise les tables CLIENTS, CIRCUITS, CHOIX, AEROPORTS_DEP et MAJORATION. La sous-requête avec EXISTS permet de vérifier qu'un client possède plusieurs présélections pour un même circuit. Le prix de chaque présélection est ensuite calculé en additionnant le prix de base (CI.PrixBase) et la majoration (M.MontantMaj).


Pour vérifier les résultats, on constate dans CHOIX que Medhi TERRANER a présélectionné le circuit "Les saveurs tunisiennes" au départ de Toulouse pour deux dates différentes. Dans CIRCUITS, son prix de base est de 700 €. Dans MAJORATION, on retrouve 80 € pour le 08/07/2026 et 45 € pour le 01/07/2026. On obtient donc 780 € pour son premier choix et 745 € pour son deuxième choix. En effectuant cette vérification sur les autres présélections, on retrouve 10 lignes concernant 5 clients, ce qui correspond aux données de notre base.


Proposition d'ajout de données :


Nous pourrions ajouter dans la table CHOIX une troisième présélection pour “Medhi TERRANER” concernant le circuit “Les saveurs tunisiennes”, avec une autre date ou un autre aéroport de départ déjà présent dans MAJORATION. Cela permettrait de vérifier que la requête affiche bien les différentes possibilités choisies par un même client et compare leurs prix en fonction des majorations.






2.2.3. Animations accessibles pendant les séjours
Énoncé : Donner, pour chaque circuit, le nom des hôtels proposant une animation le jour où les voyageurs y séjournent, en précisant le jour, le nom de l'animation et son heure de début.


Utilité métier : Permettre à l'agence de présenter aux clients les animations correspondant réellement aux jours de séjour prévus dans les hôtels.


Requête SQL :


SELECT DISTINCT CI.NomCI, H.NomH, L.JourSe, A.NomAN,
       TO_CHAR(A.HeureDeb, 'HH24:MI') AS Heure
FROM CIRCUITS CI, LOGER L, HOTELS H, ANIMATIONS A
WHERE CI.CodeCI = L.CodeCI
AND L.CodeH = H.CodeH

SELECT DISTINCT CI.NomCI, P.NomP,
       A.NomA, M.DateDepartM, AV.TempMaxMoy
FROM CIRCUITS CI, SITUER S, PAYS P, AVIS AV,
     MAJORATION M, AEROPORTS_DEP A
WHERE CI.CodeCI = S.CodeCI
AND S.CodeP = P.CodeP
AND P.CodeP = AV.CodeP
AND CI.CodeCI = M.CodeCI
AND M.CodeA = A.CodeA

AND AV.TempMaxMoy >= 35
ORDER BY AV.TempMaxMoy DESC, CI.NomCI;
